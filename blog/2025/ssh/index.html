SSH 접속 및 Job 실행하기

Created on March 10, 2025 , last updated on March 27, 2026

2025   ·   SSH   Slurm   Job

Python 사용자는 Step 1-4를 숙지한 뒤 Python 문서로 넘어가세요. R 사용자는 Step 1-4를 숙지한 뒤 R 문서로 넘어가세요.

Step 1. terminal 앱 고르기

사용자는 SSH를 통해 학과 서버에 접속하여 클러스터를 사용합니다. SSH는 원격 서버에 안전하게 접속하기 위한 표준 방식입니다. 학과 서버는 SSH를 통해 접속하며, 접속 후에는 서버의 터미널과 파일을 원격으로 사용할 수 있습니다. 터미널 환경과 vi 에디터에 익숙한 user는 자신에게 친숙한 앱을 사용하면 됩니다. 그렇지 않은 경우 Visual Studio Code를 사용하는 것을 추천합니다. 이 문서에는 Visual Studio Code를 사용하는 것을 전제로 합니다. 추천 이유는 다음과 같습니다.

  • Windows, MacOS, Linux에서 모두 사용 가능합니다.

  • 터미널과 에디터, 파일 브라우저가 통합되어 있습니다.

    • 불편하게 vi나 nano등의 CLI용 텍스트 에디터를 사용할 필요가 없습니다.

    • 파일 전송시 scp등의 복잡한 프로토콜을 사용하지 않고 drag & drop으로 수행할 수 있습니다.

2. Remote Explorer에서 REMOTES(TUNNELS/SSH)를 선택 후, + 클릭

  • ctrl + shift + ~키를 누르면 터미널이 열립니다. 여기서 서버 사용에 필요한 커맨드를 입력합니다. 터미널은 여러 개 띄울 수 있습니다.

11. user password 변경

모든 user의 초기 password가 다 동일하기 때문에, 각 user는 첫 접속 시 password를 변경할 것을 권장합니다. 터미널에서 아래 커맨드를 입력하여 password를 변경합니다.

passwd

12. 여러 서버를 사용하는 경우 (선택사항)

학과 서버는 여러 노드로 구성되어 있으므로, 사용자에 따라 둘 이상의 서버 접속 정보를 사용할 수 있습니다.
이 경우 VS Code의 SSH config 파일 안에 여러 Host 항목이 함께 저장되며, Remote Explorer에서 원하는 서버를 선택하여 접속할 수 있습니다.

Step 3. 파일 시스템 구조 이해

User명은 컴퓨팅 클러스터 사용 신청시 제출하신 이메일 주소의 @ 앞 부분과 동일합니다.

각 사용자는 로그인 시 개인 home directory가 자동으로 설정되며,
이 경로는 서버마다 다를 수 있습니다.

예를 들어:

  • hpcmaster: /data1/[username]
  • hpc: /data/home/[username]
  • hpc-stat1, brl0–brl5: /home/[username]

home directory는 코드, 데이터, 설정 파일 등을 저장하는 기본 작업 공간이며,
로그인 시 기본 위치로 설정됩니다.

경로는 서버마다 다르지만, 항상 ~ 기호로 동일하게 접근할 수 있습니다.

또한 다른 사용자의 home directory에는 접근할 수 없도록 권한이 설정되어 있습니다.

기본 명령어

  • cd: 디렉토리 이동
  • ~: home directory
  • pwd: 현재 위치 확인
  • ls: 파일 목록 확인

예시

다음 명령어를 사용하면 자신의 home directory로 이동한 뒤,
해당 위치에 있는 파일 목록을 확인할 수 있습니다.

cd ~    
ls -a

testuser@hpc:~$ ls -a
.  ..  .bash_logout  .bashrc  .cache  .config  .profile  .vscode-server  .wget-hsts

Step 4. Slurm batch script 작성하여 Job을 서버에 제출하기

앞 단계까지 진행했다면, 이제 Slurm을 이용해 실제 작업(job)을 서버에 제출할 수 있습니다.

학과 서버는 여러 노드로 구성되어 있으며, 노드마다 home directory 및 로컬 저장공간 구성이 다를 수 있습니다.
따라서 처음에는 실행할 노드를 명시하여 job을 제출하는 방식을 권장합니다.

예를 들어 현재는 아래와 같이 partition과 node를 대응시킬 수 있습니다.

  • hpc: jobs
  • hpc-stat1: partition1
  • brl0–brl5: brl

이 문서에서는 hpc에서 실행하는 예시를 사용합니다.

Step 4.1 테스트용 batch script 작성

먼저 아주 간단한 테스트 job을 만들어 보겠습니다.

Visual Studio Code에서 아래 내용을 작성하여 test.job이라는 이름으로 저장합니다. 이 파일이 Slurm에 제출할 batch script입니다.

#!/bin/bash
#SBATCH --job-name=test_job
#SBATCH --partition=jobs
#SBATCH --nodelist=hpc
#SBATCH --time=00:01:00
#SBATCH --mem=1G
#SBATCH --cpus-per-task=1
#SBATCH --output=test.log
#SBATCH --error=test.err

echo "Hello Slurm"
hostname
pwd
sleep 30
echo "Job finished"

위 script의 의미는 다음과 같습니다.

  • --job-name: 수행할 작업의 이름

  • --partition: group of nodes with specific characteristics

  • --nodelist: 사용할 node의 이름

  • --time: 작업 제한시간

  • --mem: memory limit

  • --cpus-per-task: 작업에 사용할 CPU 코어 수

  • --output: 코드 실행 결과 log 파일. 확장자는 out이나 log가 가능합니다.

  • --error: 코드 실행 결과 log error 파일과 log 파일의 파일명과 저장 경로는 원하는 데로 수정할 수 있습니다.

이 예시는 특별한 프로그램을 실행하지 않고,

  • 문자열 출력

  • 현재 실행 중인 서버 이름 확인

  • 현재 작업 경로 확인

  • 30초 대기

를 수행하는 가장 단순한 테스트 job입니다.

※ 위 예시는 간단한 테스트를 위한 설정입니다.

  • --time=00:01:00: 1분만 실행
  • --mem=1G: 최소 메모리 사용

실제 분석 작업에서는 더 많은 시간이 필요할 수 있으며,
필요 이상의 자원을 요청하면 job이 바로 실행되지 않고 대기할 수 있습니다.

Step 4.2 Job 제출

Visual Studio Code 하단 터미널에

sbatch test.job

를 입력해 slurm batch job submission을 수행합니다. 작업이 노드에서 성공적으로 실행되면

Submitted batch job 71

와 같은 메시지가 뜨고 job 번호가 할당됩니다. 할당되는 job 번호는 나중에 squeue를 통해 정보를 확인하거나 job을 취소할 때 이용되므로 기록해 놓아야 합니다.

Step 4.3 실행 상태 확인

squeue

커맨드를 통해 작업 실행 현황을 확인할 수 있습니다.

또는 아래 커맨드를 통해 실시간(10초 단위)으로 작업 실행 현황을 확인할 수 있습니다. ctrl+c로 escape 할 수 있습니다.

watch -n 10 -d squeue

또는 자신의 job만 확인하려면 다음과 같이 입력할 수 있습니다.

squeue -u $(whoami)

작업이 실행 중이면 예를 들어 아래와 비슷한 형태로 보입니다.

JOBID PARTITION     NAME     USER ST       TIME  NODES NODELIST(REASON)
   71      jobs  test_job testuser  R       0:15      1 hpc

  • R: running

  • PD: pending

을 의미합니다.

Step 4.4 현재 자원 상태 확인

job이 바로 실행되지 않거나(PD 상태), 자원 요청을 조정하고 싶을 때는 현재 서버의 자원 상태를 확인할 수 있습니다.

아래 커맨드를 통해 각 노드의 CPU와 RAM 사용 현황을 볼 수 있습니다.

sinfo -o "%n %e %m %a %c %C"

아래와 같은 결과가 나옵니다.

HOSTNAMES FREE_MEM MEMORY AVAIL CPUS CPUS(A/I/O/T)
hpc 142973 250000 up 64 42/22/0/64
hpc-stat1 100073 515653 up 128 12/116/0/128
brl0 50495 257557 up 64 16/48/0/64
brl1 149690 257551 up 64 6/58/0/64
brl2 14001 257556 up 64 50/14/0/64
brl3 72143 257613 up 64 18/46/0/64
brl4 86255 257618 up 64 4/60/0/64
brl5 103585 257617 up 96 16/80/0/96

  • CPUS의 A/I/O/T는 allocated/idle/other/total을 의미합니다.

  • 자신의 job이 바로 실행되기를 원한다면, Slurm batch script를 작성할 때

    • RAM 용량을 FREE_MEM보다 적게 설정해야 합니다.

    • CPU 코어 개수를 CPUS idle보다 적게 설정해야 합니다.

  • 실제 필요 이상의 자원을 올리면 다른 사용자의 사용에 어려움이 있을 수 있으니 반드시 필요한 만큼만 올려야 합니다.

  • 현재 가용 자원보다 더 많은 자원을 요구하는 script를 작성하면, job이 바로 실행되지 않고 대기 상태(PD)로 남을 수 있습니다.

  • 현재 제출한 job이 PD 상태로 오래 머무르는 경우에는, 자원 여유가 더 많은 다른 노드를 선택하여 다시 제출하는 것도 한 가지 방법입니다. 이때는 node 이름뿐 아니라 해당 node가 속한 partition도 함께 맞추어야 합니다.

    • 예를 들어 hpc 대신 hpc-stat1에서 실행하려면, batch script에서 --partition=partition1과 --nodelist=hpc-stat1를 함께 수정해야 합니다.

Step 4.5 로그 확인

다음 커맨드를 통해 output log, error log파일의 내용을 확인할 수 있습니다.

cat test.log
cat test.err

log 파일의 내용을 다음 커맨드를 통해 실시간으로 확인할 수 있습니다. ctrl+c로 escape할 수 있습니다.

tail -f test.log
tail -f test.err

터미널을 여러 개 띄워 놓고 각각에 squeue와 tail 커맨드를 입력하면 편리하게 실행 상황을 모니터링할 수 있습니다.

위 test job이 정상적으로 끝났다면 test.log에는 아래와 비슷한 내용이 남습니다.

Hello Slurm
hpc
/data/home/testuser
Job finished

  • hpc는 실제 실행된 node 이름

  • /data/home/testuser는 해당 서버에서의 작업 경로 예시

를 의미합니다.

Step 4.6 Job 정보 자세히 확인하기

scontrol show job [job number]

이 명령어를 사용하면

  • 어떤 partition에 제출되었는지

  • 어느 node에서 실행 중인지

  • 몇 개의 CPU와 얼마나 많은 memory를 요청했는지

  • output / error 파일 경로가 어디인지

등을 자세히 확인할 수 있습니다.

Step 4.7 Job 취소하기

작업이 끝나기 전에 취소하려면 scancel 명령어를 사용합니다.

scancel [job_number]

Step 5. Slurm job configurator 사용하기 (선택사항)

클러스터 소개 페이지의 Slurm job configurator를 사용하면 batch script를 조금 더 쉽게 작성할 수 있습니다.

  • USERNAME, JOBNAME, NODE, CPU, MEMORY, TIME을 입력합니다.
    • CPU와 MEMORY는 현재 선택한 node의 가용 자원을 참고하여 설정합니다.
    • 실제 필요 이상의 자원을 요청하면 job이 대기 상태(PD)로 오래 머무를 수 있으므로, 필요한 만큼만 설정하는 것이 좋습니다.
    • TIME은 작업이 실제로 끝날 수 있도록 너무 짧지 않게 설정하는 것이 좋습니다.
  • Script란에는 실제로 실행할 명령어를 작성합니다.
    예를 들어 python은 python xxx.py, R은 Rscript xxx.R와 같이 입력할 수 있습니다.
  • Print & Copy 버튼을 누르면 현재 설정을 반영한 Slurm batch script가 자동으로 생성되어 클립보드에 복사됩니다.

configurator는 선택한 NODE에 따라 아래 항목을 자동으로 설정합니다.

  • --partition
  • --nodelist
  • --output, --error 경로 (home directory 기준)

예를 들어:

  • hpc 선택 → partition=jobs, /data/home/[username]
  • hpc-stat1 선택 → partition=partition1, /home/[username]
  • brl0–brl5 선택 → partition=brl, /home/[username]

따라서 사용자는 node만 선택해도 해당 서버 환경에 맞는 script를 자동으로 생성할 수 있습니다.

다만 configurator가 생성한 script는 편의를 위한 기본 템플릿이므로, 실제 제출 전에 아래 항목을 한 번 더 확인하는 것이 좋습니다.

  • --partition
  • --nodelist
  • --mem, --cpus-per-task
  • --output, --error 경로
  • Script 내용

복사한 script는 .job 파일로 저장한 뒤, 앞선 Step 4와 동일하게 sbatch 명령어로 제출하면 됩니다. 또한 원이 부족하여 job이 PD 상태로 오래 머무르는 경우에는, 다른 node를 선택하여 다시 생성 및 제출할 수 있습니다.

Visual Studio Code의 file explorer는 실시간으로 변화가 반영되지 않습니다. 새로고침 버튼을 눌러 주면 변화가 반영되고 output 파일이 explorer에 보입니다.
