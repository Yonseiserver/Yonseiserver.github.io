## Step 1. 필요한 R 패키지를 자신의 디렉토리에 설치하기
   
상경대학 서버에서 R 패키지는 사용자별로 별도 설치하여 사용하는 것을 권장합니다. 기본 설정으로 설치하면 서버 환경에 따라 사용자별 라이브러리 경로가 자동으로 잡히기도 하지만, 패키지 관리와 경로 확인을 쉽게 하기 위해 직접 라이브러리 디렉토리를 만들어 사용하는 것이 더 편리합니다.

먼저 home directory 아래에 `R_packages` 디렉토리를 생성합니다.  
터미널에서 아래 명령어를 입력하면 자신의 home directory 아래에 `R_packages` 폴더가 생성됩니다.

   
```
mkdir -p ~/R_packages
```
   
아래의 샘플 코드는 R 패키지를 `~/R_packages` 라는 디렉토리에 설치합니다. **install.packages()**에서
   
- `lib` 옵션을 통해 자신의 개인 디렉토리에 패키지를 설치할 수 있습니다. 이 옵션을 사용하지 않으면 사용자 간에 패키지 버전이 충돌할 수 있으므로 이 옵션을 사용하는 것을 강력히 권장합니다.

- `force = FALSE` 옵션은 이미 설치된 패키지를 또 설치하는 것을 막아줍니다.

- `INSTALL_opts = c('–no-lock')` 옵션은 설치가 이전에 강제로 중단되어서 directory에 락이 걸렸을 때 락을 무시하고 설치하게 합니다.
   
```
lib_r_packages = path.expand("~/R_packages")
install.packages(
"WeightSVM",
lib = lib_r_packages,
dependencies = TRUE,
force = FALSE,
INSTALL_opts = c('--no-lock')
)
install.packages(
"e1071",
lib = lib_r_packages,
dependencies = TRUE,
force = FALSE,
INSTALL_opts = c('--no-lock')
)
```
   
위 코드를 `User home directory`에 `install_R_packages.R`로 저장합니다. 이제 [SSH 접속 및 Job 실행하기](/blog/2025/ssh/index.html) 문서의 Step 4를 참고해 `Rscript install_R_packages.R`를 실행하는 Slurm batch script를 작성한 뒤 `sbatch`로 제출합니다.
   


## Step 2. R 코드 작성
    
클러스터에서 실행할 `R` 코드를 local에서 작성합니다. 코드가 문제 없이 실행되는지 먼저 local에서 확인합니다. 그 후 실제로 실행할 코드를 작성하여 클러스터의 `User home directory`에 옮기거나, `Visual Studio Code`내에서 작성하여 저장합니다.
   
아래의 샘플 코드는 `e1071` 패키지의 `svm()` 함수를 이용해 회귀모형을 학습하고, 예측 결과 plot을 jpeg 파일로 저장하는 예시입니다. `library(e1071, lib.loc = lib_r_packages)` 에서 `lib.loc` 옵션이 개인 디렉토리에 설치된 패키지를 로드하는 옵션입니다. 

또한 Slurm batch script로 작업을 제출할 때는 알고리즘의 output이 자동으로 저장되지 않으므로 파일로 결과를 저장하는 코드를 포함하는 것이 좋습니다. 

아래 코드를 `R_test.R`로 저장하여 `User home directory`에 둡니다.
   
``` 
lib_r_packages = path.expand("~/R_packages")

library(e1071, lib.loc = lib_r_packages)

data(iris)

set.seed(12)

# 데이터 크기를 일부러 늘림
iris_big = iris[rep(1:nrow(iris), 80), ]
iris_big$noise1 = rnorm(nrow(iris_big))
iris_big$noise2 = rnorm(nrow(iris_big))
iris_big$noise3 = rnorm(nrow(iris_big))

cat("Start tuning SVM...\n")

tuned = tune.svm(
  Species ~ .,
  data = iris_big,
  kernel = "radial",
  cost = c(0.1, 1, 10, 100),
  gamma = c(0.001, 0.01, 0.1, 1),
  tunecontrol = tune.control(cross = 5)
)

cat("Tuning finished.\n")
print(summary(tuned))

perf = tuned$performances
g = sort(unique(perf$gamma))
c = sort(unique(perf$cost))
z = xtabs(error ~ gamma + cost, data = perf)

jpeg("R_plot.jpeg", width = 800, height = 700)
filled.contour(
  x = g,
  y = c,
  z = z,
  color.palette = heat.colors,
  plot.axes = {
    axis(1)
    axis(2)
    contour(x = g, y = c, z = z, add = TRUE, drawlabels = TRUE)
  },
  xlab = "gamma",
  ylab = "cost",
  main = "Cross-validation Error of SVM"
)
dev.off()

write.csv(tuned$performances, "svm_tuning_results.csv", row.names = FALSE)
```
   


## Step 3. 현재 클러스터 자원 사용량 확인
   
아래 커맨드를 통해 각 노드의 cpu와 RAM 사용 현황을 볼 수 있습니다.
   
```
sinfo -o "%n %e %m %a %c %C"
```
   
아래와 같은 결과가 나옵니다.
   
```
HOSTNAMES FREE_MEM MEMORY AVAIL CPUS CPUS(A/I/O/T)
hpc 142973 250000 up 64 42/22/0/64
hpc-stat1 100073 515653 up 128 12/116/0/128
brl0 50495 257557 up 64 16/48/0/64
brl1 149690 257551 up 64 6/58/0/64
brl2 14001 257556 up 64 50/14/0/64
brl3 72143 257613 up 64 18/46/0/64
brl4 86255 257618 up 64 4/60/0/64
brl5 103585 257617 up 96 16/80/0/96
```
   
- CPUS의 A/I/O/T는 allocated/idle/other/total을 의미합니다.

- 자신의 job이 바로 실행되기를 원한다면, Slurm batch script를 작성할 때

    - RAM 용량을 FREE_MEM보다 적게 설정해야 합니다.

    - CPU 코어 개수를 CPUS idle보다 적게 설정해야 합니다.

    - 실제 필요 이상의 자원을 올리면 다른 사용자의 사용에 어려움이 있을 수 있으니 반드시 필요한 만큼만 올려야 합니다.

- 현재 가용 자원보다 더 많은 자원을 요구하는 script를 작성하면, job이 바로 실행되지 않습니다. 대기 상태에 있다가 다른 user들의 job이 끝나고 자원이 반환되면 job이 실행됩니다.
   


## Step 4. Slurm batch script 작성
   
작성한 코드를 해당 node에서 실행하는 Slurm batch script를 작성합니다. 클러스터 소개 페이지의 slurm job configurator를 사용하면 script를 쉽게 작성할 수 있습니다. 이 문서에서는 `hpc-stat1`에서 실행하는 예시를 사용합니다.

![이미지24](/assets/img/img24.png)
   

- `USERNAME`, `JOBNAME`, `NODE`, `CPU`, `MEMORY`, `TIME`을 입력합니다.
- `Script`란에는 `Rscript xxx.R`와 같이 실제로 실행할 명령어를 작성합니다.
- `Print & Copy` 버튼을 누르면 batch script가 자동으로 생성되어 클립보드에 복사됩니다.

   
Configurator로 생성한 Slurm batch script의 내용은 아래와 같습니다.
   
``` bash
#!/bin/bash
#
#SBATCH --job-name=test_R
#SBATCH --partition=partition1
#SBATCH --mem=16G
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=4
#SBATCH --time=00:50:00
#SBATCH --output=/home/$(whoami)/test_R.log
#SBATCH --error=/home/$(whoami)/test_R.err
#SBATCH --nodelist=hpc-stat1

Rscript R_test.R
```
   
`R_test.job`이라는 이름으로 `user home directory`에 저장합니다.


## Step 5. Slurm batch script 실행
   
`sbatch` 커맨드를 통해 job을 제출합니다. [SSH 접속 및 Job 실행하기](/blog/2025/ssh/index.html) 문서의 Step 4에서처럼, `ctrl+shift+~`를 눌러 터미널을 여러 개 띄우고 `watch -n 10 -d squeue`로 작업 현황을 확인하고, `tail -f xxx.out`, `tail -f xxx.err`으로 콘솔 출력이나 error를 확인합니다.
   
```
sbatch R_test.job
```
이 예시 job은 `hpc-stat1` 기준으로 약 1~2분 정도 소요될 수 있습니다.  
따라서 제출 후 바로 끝나지 않더라도 정상일 수 있으며, `squeue`나 로그 파일을 통해 진행 상황을 확인할 수 있습니다.

   
작업이 정상적으로 완료되면 home directory에 하이퍼파라미터 탐색 결과를 시각화한 `R_plot.jpeg`와,  
각 조합별 성능이 저장된 `svm_tuning_results.csv` 파일이 생성됩니다.

![이미지21](/assets/img/img21.jpeg)

`svm_tuning_results.csv`에는 각 `gamma`, `cost` 조합에 대한 교차검증 오차(`error`)와 분산(`dispersion`) 정보가 저장됩니다.

만약 이러한 결과 파일이 생성되지 않았다면, 로그 파일(`.log`, `.err`)을 먼저 확인해 보시기 바랍니다.  
특히 필요한 R 패키지가 설치되지 않았거나, 설치 job의 실행 시간이 부족했던 경우 오류가 발생할 수 있습니다.
