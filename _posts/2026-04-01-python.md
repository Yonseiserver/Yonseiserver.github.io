## Step 1. Miniconda 설치

기존에는 서버에 설치된 공용 conda를 기준으로 Python 환경 생성을 안내하였으나,  
이제는 사용자별로 독립적인 Python 환경을 관리할 수 있도록 각자 miniconda를 설치하여 사용하는 방식을 권장합니다.

Miniconda는 최소한의 conda 환경만 포함한 Python 배포판입니다.  
이를 사용하면 각 사용자가 필요한 Python 버전과 패키지를 자신의 경로 아래에서 독립적으로 관리할 수 있습니다.

이 문서에서는 miniconda를 `/mnt/data1/[username]/miniconda3` 경로에 설치하는 것을 기준으로 설명합니다.

### Step 1.1 설치 파일 다운로드

먼저 터미널에서 `/mnt/data1/[username]` 아래에 다운로드용 디렉토리를 만들고, miniconda 설치 파일을 내려받습니다.

```bash
cd /mnt/data1/$USER
mkdir -p downloads
cd downloads
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
```

설치 파일의 크기는 약 155MB 정도이며, 다운로드에는 네트워크 상황에 따라 수십 초 정도 걸릴 수 있습니다.

### Step 1.2 miniconda 설치

아래 명령어를 실행하여 miniconda를 설치합니다.
  
```bash
bash Miniconda3-latest-Linux-x86_64.sh -b -p /mnt/data1/$USER/miniconda3
```
- -b 옵션은 설치 과정에서 추가 입력 없이 batch mode로 설치하라는 의미입니다.

- -p 옵션은 설치 경로를 지정하는 옵션입니다.


설치가 정상적으로 완료되면 아래와 같이 `installation finished.` 메시지가 출력됩니다.

```bash
PREFIX=/mnt/data1/$USER/miniconda3
Unpacking bootstrapper...
Unpacking payload...

Installing base environment...

Preparing transaction: ...working... done
Executing transaction: ...working... done
installation finished.
```

설치 과정에서 `Unpacking payload...` 단계가 다소 오래 걸릴 수 있습니다.
이는 정상적인 설치 과정이므로, error 메시지가 없다면 잠시 기다리면 됩니다.

### Step 1.3 설치 확인

아래 명령어를 실행하여 miniconda가 정상적으로 설치되었는지 확인합니다.
```
/mnt/data1/$USER/miniconda3/bin/conda --version
ls /mnt/data1/$USER/miniconda3
```
예를 들어 아래와 같이 conda 버전이 출력되면 정상적으로 설치된 것입니다.
```
conda 26.1.1
```
또한 `bin`, `envs`, `etc`, `lib`, `pkgs` 등의 디렉토리가 보이면 설치가 완료된 상태입니다.

### Step 1.4 conda 명령어 활성화 확인

현재 셸에서 conda 명령어를 사용할 수 있도록 아래 명령어를 입력합니다.
```
source /mnt/data1/$USER/miniconda3/etc/profile.d/conda.sh
conda activate
```
정상적으로 활성화되면 프롬프트 앞에 `(base)`가 표시됩니다.

이후 아래 명령어로 python과 conda가 사용자 miniconda 경로를 가리키는지 확인합니다.
```
which python
which conda
```
예를 들어 계정이 testuser 경우 아래와 같이 출력되면 정상입니다.
```
/mnt/data1/testuser/miniconda3/bin/python
/mnt/data1/testuser/miniconda3/bin/conda
```
여기까지 완료되면 miniconda 설치가 끝난 것입니다.

### Step 1.5 Terms of Service 수락
최신 miniconda/conda에서는 기본 채널 사용 전에 Terms of Service 수락이 필요할 수 있습니다.
아래 명령어를 한 번 실행해 두면 이후 Python environment 생성 과정에서 관련 오류를 줄일 수 있습니다.
```
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
```

정상적으로 완료되면 아래와 같은 메시지가 출력됩니다.
```
accepted Terms of Service for https://repo.anaconda.com/pkgs/main
accepted Terms of Service for https://repo.anaconda.com/pkgs/r
```
여기까지 완료되면 miniconda 설치가 끝난 것입니다.

## Step 2. Python environment 생성

이 단계에서는 앞에서 설치한 miniconda를 사용하여 Python environment를 생성합니다.  
학과 서버에서는 장시간 작업이나 패키지 설치를 Slurm job으로 수행하는 것을 권장하므로,  
Python environment 생성도 batch script를 작성하여 제출하는 방식으로 설명합니다.

이번 문서에서는 miniconda는 `/mnt/data1/[username]/miniconda3` 아래에 설치하지만,  
`.job` 파일은 `user home directory`에 저장하고 실행하는 것을 기준으로 설명합니다.

따라서 Step 1에서 miniconda를 설치할 때 `/mnt/data1/[username]/downloads` 등 다른 경로에 있었다면,  
Python environment 생성용 job을 실행하기 전에 다시 `user home directory`로 이동해야 합니다.

예를 들어 아래와 같이 `downloads` 경로에서는 `create_py311.job` 파일을 찾지 못할 수 있습니다.

```bash
testuser@hpc-stat1:/mnt/data1/testuser/downloads$ sbatch create_py311.job
sbatch: error: Unable to open file create_py311.job
testuser@hpc-stat1:/mnt/data1/testuser/downloads$ cd /home/testuser
```
이 매뉴얼에서는 설명의 일관성을 위해 `hpc-stat1` 노드에서 작업하는 예시를 사용합니다.

### Step 2.1 Python environment 생성 batch script 작성

아래는 `py311`이라는 이름의 Python 3.11 환경을 생성하고, 필요한 패키지를 함께 설치하는 예시입니다.

```bash#!/bin/bash
#SBATCH --job-name=create_py311
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --time=02:00:00
#SBATCH --mem=4gb
#SBATCH --nodelist=hpc-stat1
#SBATCH --partition=partition1
#SBATCH --output=create_py311.log
#SBATCH --error=create_py311.err

set -euo pipefail

CONDA_ROOT=/mnt/data1/$(whoami)/miniconda3
ENV_PATH=$CONDA_ROOT/envs/py311

source $CONDA_ROOT/etc/profile.d/conda.sh
conda activate base

if [ -d "$ENV_PATH" ]; then
  rm -rf "$ENV_PATH"
fi

conda create -y --prefix "$ENV_PATH" python=3.11
```
위 스크립트를 `create_py311.job`이라는 이름으로 `user home directory`에 저장합니다.

- `CONDA_ROOT`는 miniconda가 설치된 경로입니다.
- `ENV_PATH`는 생성할 Python environment의 경로입니다.
- `conda activate base`는 miniconda의 base environment를 활성화하는 명령입니다.
- `if [ -d "$ENV_PATH" ]; then ... fi` 구문은 같은 이름의 environment가 이미 있을 경우 삭제한 뒤 다시 생성하도록 하는 부분입니다.

```
set -euo pipefail
```

위 옵션은 shell script 실행 중 오류를 더 명확하게 확인하기 위해 넣는 설정입니다.
- -e: 중간에 명령어가 실패하면 즉시 종료
- -u: 정의되지 않은 변수를 사용하면 오류 처리
- -o pipefail: 파이프라인(|) 안의 명령어 중 하나라도 실패하면 전체를 실패로 처리

이 옵션을 넣으면 중간에 오류가 발생했을 때 이후 명령이 계속 실행되는 것을 막을 수 있습니다.

### Step 2.2 작성한 스크립트 실행 및 결과 확인
터미널에서 user home directory로 이동한 뒤 아래 명령어를 입력하여 job을 제출합니다.
```
cd ~
sbatch create_py311.job
```
작업이 정상적으로 제출되면 아래와 같은 메시지가 출력됩니다.
```
Submitted batch job [job number]
```

로그 파일에 `Executing transaction: ... done`과 아래와 같은 메시지가 보이면 정상적으로 environment가 생성된 것입니다.
```
# To activate this environment, use
#
#     $ conda activate /mnt/data1/testuser/miniconda3/envs/py311
#
# To deactivate an active environment, use
#
#     $ conda deactivate
```
## Step 3. 필요한 패키지 설치

Python environment를 생성한 뒤에는 필요한 패키지를 설치합니다. 패키지 이름은 conda에서 사용하는 이름을 정확히 입력해야 하며, Python 기본 내장 패키지는 별도로 설치할 필요가 없습니다.

### Step 3.1 패키지 설치 batch script 작성

아래는 `py311` environment에 `pandas`, `scikit-learn`, `lightgbm`를 설치하는 예시입니다.

```bash
#!/bin/bash
#SBATCH --job-name=install_py311
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --time=02:00:00
#SBATCH --mem=4gb
#SBATCH --nodelist=hpc-stat1
#SBATCH --partition=partition1
#SBATCH --output=install_py311.log
#SBATCH --error=install_py311.err

set -euo pipefail

CONDA_ROOT=/mnt/data1/$(whoami)/miniconda3
ENV_PATH=$CONDA_ROOT/envs/py311

source $CONDA_ROOT/etc/profile.d/conda.sh
conda activate "$ENV_PATH"

conda install -y -c conda-forge numpy pandas scikit-learn lightgbm
```
위 스크립트를 `install_py311.job`이라는 이름으로 `user home directory`에 저장합니다.

### Step 3.2 작성한 스크립트 실행 및 결과 확인

터미널에서 `user home directory`로 이동한 뒤 아래 명령어를 입력하여 job을 제출합니다.

```

설치가 완료된 뒤에는 아래 명령어로 패키지가 정상적으로 설치되었는지 확인할 수 있습니다.

```

## Step 4. Python 코드 실행

앞선 단계에서 만든 Python environment를 사용하여 Python 코드를 실행합니다.  
이번 단계에서는 실행할 Python 코드를 준비하고, Slurm batch script를 작성하여 서버에 제출하는 과정을 설명합니다.

### Step 4.1 Python 코드 작성
   
이제 클러스터에서 실행할 Python 코드를 local에서 작성합니다. 코드가 오류 없이 작동하는지 local에서 확인합니다. 그 후 코드 파일을 `user home directory`에 옮기거나, `Visual Studio Code`내에서 작성하여 저장합니다.
   
아래는 tree 기반 boosting 알고리즘인 LightGBM으로 mnist dataset을 분류하는 코드입니다. Boosting round를 10회 수행하고 학습 결과를 csv파일로 저장합니다. 

Batch script를 작성할 때는 알고리즘의 output이 자동으로 저장되지 않으므로 파일로 결과를 저장하는 코드를 포함하는 것이 좋습니다. 단, 콘솔에 출력되는 내용은 output log에 자동으로 기록됩니다. 

아래 코드를 `python_test.py`로 저장하여 `user home directory`에 둡니다.
   
``` python
import numpy as np
from time import process_time
from lightgbm import LGBMClassifier
from sklearn.metrics import accuracy_score, log_loss
from sklearn.datasets import fetch_openml
from sklearn.model_selection import train_test_split


def lgb(n=10, c=0, sequence=1):

    mnist = fetch_openml('mnist_784')
    x_train, x_test, y_train, y_test = train_test_split(mnist.data, mnist.target, test_size=0.33, random_state=42)



    proba_test = np.zeros((n, y_test.shape[0], len(np.unique(y_test))))
    proba_train = np.zeros((n, y_train.shape[0], len(np.unique(y_train))))

    test_score = []
    train_score = []

    tr_time = []
    seq = []
    while(n):

        model = LGBMClassifier(n_estimators=sequence)

        t0 = process_time()
        model.fit(x_train, y_train)
        tr_time.append(process_time() - t0)
        test_score.append(accuracy_score(y_test, model.predict(x_test)))
        train_score.append(accuracy_score(y_train, model.predict(x_train)))
        proba_test[c, ] = model.predict_proba(x_test)
        proba_train[c, ] = model.predict_proba(x_train)

        seq.append(sequence)
        sequence *= 2
        n -= 1
        c += 1

        ce_train = []
        ce_test = []

    for i in range(10):
        ce_test.append(log_loss(y_test, proba_test[i]))
        ce_train.append(log_loss(y_train, proba_train[i]))

        np.savetxt('round'+ str(i) + 'proba_test.csv', proba_test[i])
        np.savetxt('round'+ str(i) + 'proba_train.csv', proba_train[i])

    np.savetxt('test_score.csv', test_score, delimiter=',')
    np.savetxt('train_score.csv', train_score, delimiter=',')

    np.savetxt('ce_test.csv', ce_test, delimiter=',')
    np.savetxt('ce_train.csv', ce_train, delimiter=',')


if __name__ == '__main__':
    lgb()
```



### Step 4.2 Slurm batch script 작성
   
앞선 단계에서 생성한 `py311` Python environment를 activate하고 Python 코드를 실행하는 Slurm batch script를 작성합니다.

자원 설정(`--time`, `--mem`, `--cpus-per-task`, `--partition` 등)은 SSH 문서의 안내를 참고하여 작업에 맞게 조정합니다. 기존에 작성한 Slurm configuration 파일이 있다면, 아래와 같이 **miniconda / Python environment 활성화 부분과 `python python_test.py` 실행 부분만 추가 또는 수정**하면 됩니다.

아래는 `python_test.py`를 실행하는 예시입니다.
   
``` bash
#!/bin/bash
#
#SBATCH --job-name=python_test
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=4
#SBATCH --time=02:00:00
#SBATCH --mem=4gb
#SBATCH --nodelist=hpc-stat1
#SBATCH --partition=partition1
#SBATCH --output=python_test.log
#SBATCH --error=python_test.err

# Set up conda environment
CONDA_ROOT=/mnt/data1/$(whoami)/miniconda3
ENV_PATH=$CONDA_ROOT/envs/test_py311

source $CONDA_ROOT/etc/profile.d/conda.sh
conda activate "$ENV_PATH"

python python_test.py
```
   
위 스크립트를 `python_test.job`이라는 이름으로 `user home directory`에 저장합니다.
   
Script 윗부분의 #SBATCH 옵션들의 의미는 다음과 같습니다.
   
- `CONDA_ROOT`는 miniconda가 설치된 경로입니다.

- `ENV_PATH`는 앞 단계에서 생성한 Python environment의 경로입니다.

- `source .../conda.sh`는 현재 shell에서 conda 명령어를 사용할 수 있도록 설정하는 부분입니다.

- `conda activate "$ENV_PATH"`는 해당 Python environment를 활성화하는 명령입니다.


### Step 4.3 Slurm batch script 실행
   
`sbatch` 커맨드를 통해 job을 제출합니다. 할당되는 job 번호는 나중에 `squeue`를 통해 정보를 확인하거나 job을 취소할 때 이용되므로 기록해 놓아야 합니다.

```
sbatch python_test.job
```
   
`ctrl+shift+~`를 눌러 터미널을 여러 개 띄우고 `watch -n 10 -d squeue`로 작업 현황을 확인하고, `tail -f xxx.out`, `tail -f xxx.err`으로 콘솔 출력이나 error를 확인합니다. 작업은 4분 정도 걸립니다.
   

   
현재 작업이 자원을 얼마나 할당받았는지 확인하려면 아래 명령어를 사용합니다. 이 명령어는 다른 user가 제출한 job에 대해서도 사용할 수 있습니다.
   
```
scontrol show job [job number]
```

`Visual Stuio Code`의 file explorer는 실시간으로 변화가 반영되지 않을 수 있습니다. 새로고침 버튼을 눌러 주면 변화가 반영되고 output 파일이 explorer에 보입니다.
   
예시 코드가 정상적으로 실행되면 `round0proba_test.csv`, `round0proba_train.csv`, ..., `round9proba_test.csv`, `round9proba_train.csv` 와 함께 `test_score.csv`, `train_score.csv`, `ce_test.csv`, `ce_train.csv` 파일이 생성됩니다.  
이 파일들이 모두 생성되었다면 Python 코드가 정상적으로 실행된 것입니다.

## Step 5. TensorFlow 예시
이 단계는 TensorFlow 관련 패키지를 설치하고 실행하는 **예시**를 보여주기 위한 것이며, 모든 사용자가 반드시 TensorFlow를 설치해야 하는 것은 아닙니다.

앞선 단계에서 생성한 `py311` environment에 TensorFlow 등 추가 패키지를 설치하여 사용할 수 있습니다.  
필요에 따라 원하는 버전을 지정하여 설치할 수 있습니다.

```bash
#!/bin/bash
#SBATCH --job-name=install_tf
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --time=02:00:00
#SBATCH --mem=4gb
#SBATCH --nodelist=hpc-stat1
#SBATCH --partition=partition1
#SBATCH --output=install_tf.log
#SBATCH --error=install_tf.err

CONDA_ROOT=/mnt/data1/$(whoami)/miniconda3
ENV_PATH=$CONDA_ROOT/envs/py311

source $CONDA_ROOT/etc/profile.d/conda.sh
conda activate "$ENV_PATH"

conda install -y -c conda-forge tensorflow=2.12.0
```
앞선 단계와 마찬가지로, 해당 Python environment를 활성화하는 코드를 함께 작성해야 설치 명령이 올바른 environment에서 실행됩니다. 위 스크립트를 `install_tf.job`이라는 이름으로 `user home directory`에 저장한 뒤 실행합니다.

```
cd ~
sbatch install_tf.job
```

패키지 설치 시간은 서버 상태와 네트워크 상황에 따라 달라질 수 있으며, 다소 오래 걸릴 수 있습니다 (약 30분).

위 예시는 CPU 환경에서의 기본적인 TensorFlow 설치 예시입니다.  
GPU를 사용하는 경우에는 `cudatoolkit`, `cudnn` 등 추가 패키지 설치나 버전 호환성 확인이 필요할 수 있습니다.

## Step 5.2 TensorFlow 코드 실행

아래는 TensorFlow 공식 예제의 간단한 코드입니다. 이를 `tensor.py`라는 이름으로 `user home directory`에 저장합니다.

``` python
# tensor.py

import tensorflow as tf

mnist = tf.keras.datasets.mnist

(x_train, y_train), (x_test, y_test) = mnist.load_data()
x_train, x_test = x_train / 255.0, x_test / 255.0

model = tf.keras.models.Sequential([
  tf.keras.layers.Flatten(input_shape=(28, 28)),
  tf.keras.layers.Dense(128, activation='relu'),
  tf.keras.layers.Dropout(0.2),
  tf.keras.layers.Dense(10, activation='softmax')
])

model.compile(optimizer='adam',
              loss='sparse_categorical_crossentropy',
              metrics=['accuracy'])

model.fit(x_train, y_train, epochs=5)

model.evaluate(x_test,  y_test, verbose=2)
```
아래는 위 `tensor.py`를 실행하는 Slurm batch script 예시입니다.
```
#!/bin/bash
#SBATCH --job-name=tensor
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=8
#SBATCH --time=02:00:00
#SBATCH --mem=4gb
#SBATCH --nodelist=hpc-stat1
#SBATCH --partition=partition1
#SBATCH --output=tensor.log
#SBATCH --error=tensor.err

set -euo pipefail

CONDA_ROOT=/mnt/data1/$(whoami)/miniconda3
ENV_PATH=$CONDA_ROOT/envs/py311

source $CONDA_ROOT/etc/profile.d/conda.sh
conda activate "$ENV_PATH"

python tensor.py
```
위 스크립트를 `tensor.job`이라는 이름으로 `user home directory`에 저장한 뒤 실행합니다.
터미널을 여러 개 띄운 다음 `watch -n 10 -d squeue`로 작업 현황을 확인하고, `cat xxx.log`이나 `tail -f xxx.err`으로 콘솔 출력이나 error를 확인합니다.
   
```
sbatch tensor.job
watch -n 10 -d squeue # 작업 현황을 10초마다 갱신하여 보여줍니다. ctrl+c로 escape 할 수 있습니다.
cat tensor.log
tail -f tensor.err
```
